Connect & Feeds

Paste your Readwise Reader API token. It is stored only in this browser on this device, never in the app source. The app asks Readwise for your Later list first, then New, up to 25 documents, with full text.

The app tries Readwise direct first. Because the Readwise API sends no CORS headers, direct calls usually fail in a browser; if you have set your own proxy in Settings, the app retries through it and the status line names the path in use (Direct / Proxy). If both fail, nothing is broken: the reader falls back to demo mode with the two bundled samples.

Add an RSS feed

Paste an RSS or Atom feed URL. The latest 25 items become readable documents in the library, fetched direct first, then through your proxy if one is set.

Help

Try it without glasses

Install the Meta Ray-Ban Display Simulator Chrome extension, open this page's HTTPS URL in the simulator, and drive it with the arrow keys and Enter. Swipes on the Neural Band arrive as arrow keys; a pinch arrives as Enter.

Load it on the glasses

In the Meta AI app, turn on Developer Mode by tapping the app version number 5 times. Then open Display Glasses settings → App Connections → Web Apps → Add a Web App, and paste this page's HTTPS URL. Requires glasses software v125 or later and Meta AI app v272 or later.

Reading controls

Up / Down: previous / next sentence. Left / Right: jump five sentences. Enter: play or pause read-aloud. Escape or Backspace: back to the library. Your place is saved on the device as you read.

Voices

The glasses voice (speech synthesis) is the default and works offline. Unreal Speech, the engine Readwise Reader uses for listening, is optional: get a free key at unrealspeech.com (250,000 characters per month on the free tier), paste it in Settings, and pick a voice. The key stays on the device. If Unreal fails for a sentence, the app says why and reads that sentence with the glasses voice instead.

Your own proxy (for Readwise & RSS)

Readwise sends no CORS headers, so browsers block direct calls. The fix is a small Cloudflare Worker you deploy yourself: worker.js in the project repo, deployed free with npx wrangler deploy. Paste the Worker URL in Settings → API proxy URL. Its /readwise/… path forwards to the Readwise API and its /fetch?url=… path fetches feed URLs, both with CORS headers added. If you set a PROXY_SECRET on the Worker, put the same value in Settings → Proxy key. Your Readwise token only ever goes to Readwise and to your own Worker — no public third-party proxy is used. The same proxy fallback applies to RSS feeds that block cross-origin reads.

RSS feeds

On the Connect screen, paste any RSS or Atom feed URL; the latest 25 items land in the library with an RSS badge, and the feed is remembered on the device until you remove it there.

Kindle books

Kindle has no public API for book text, so Kindle books only work here as DRM-free EPUBs that you have added to Readwise Reader.

About this demo

This public build bundles no book. The library contains two short demo samples written for this app, plus anything you load yourself through Connect.

Showcase submission packet

Everything for the Meta Web Apps showcase form, prepared against this demo build. The form itself is at developers.meta.com/wearables/web-apps-submission. Meta is clear about what it offers: if selected, the app is highlighted on Meta's socials, website, or at events. It is exposure, not free hardware — there is no free Display program attached to it, and the on-device discovery lists are not taking submissions yet.

1 · Make the repo public? Yes — for this demo build

Appropriate to publish: the demo code with the book removed. This build contains no book text (only the two original demo samples), no API keys or tokens in source — the Readwise token, Unreal key, and proxy settings are typed by each user and kept in their own device's local storage — and no personal data.

But not by flipping the existing repo: the current private repo's git history contains the version with a full preloaded book embedded, so making that repo public would expose the book through its history even with the file deleted. Publish the demo as a fresh repo (or fresh, history-free history) containing only this demo build. The book version stays private, history and all.

2 · Deploy on johnyoonh.github.io

  1. First rename the existing private book repo (GitHub → repo Settings → General → Repository name) to display-reader-book. It stays private; renaming frees the display-reader name, which one account can only use once.
  2. Then create a fresh public repo named display-reader — new history, no inherited commits — and push this demo as a single static file (index.html) plus worker.js / wrangler.toml for the optional proxy. No build step, no server.
  3. In the new repo: Settings → Pages → deploy from the default branch, root folder. This is project Pages on that repo; your personal site repo (johnyoonh.github.io) is untouched.
  4. Public URL once Pages is live (this is the URL the showcase form asks for):
